# `@filosign/client`

Thin Vite UI over [`@filosign/react`](../../packages/react-sdk/README.md). Pages, layout, and route-scoped controllers live here; API hooks, wallet session, and oRPC wiring live in the SDK.

> **Audience:** contributors and AI agents. Read this before adding routes, controllers, or client-only queries.

## Quick rules

1. **Server data:** `@filosign/react` domain hooks (`@filosign/react/files`, `/sharing`, `/auth`, …)—not raw `fetch` to `/api/rpc`.
2. **Queries:** spread `rpcQuery.*.queryOptions()`; gate with `enabled: isAuthed` (or the hook’s built-in gate). See [TanStack Query](#tanstack-query).
3. **Invalidation:** `@filosign/react/invalidate-queries` or `rpcQuery.<domain>.key()`—never ad-hoc string tuples for API data.
4. **New API surface:** server procedure → SDK hook → thin client controller/page ([vertical slice](../../AGENTS.md#vertical-slice)).
5. **Never** put `rpc` in a `queryKey` (proxy + `JSON.stringify` hazard—root [`AGENTS.md`](../../AGENTS.md)).

Deeper SDK detail: [`packages/react-sdk/README.md`](../../packages/react-sdk/README.md). Repo map: [`AGENTS.md`](../../AGENTS.md).

## Routing (TanStack Router)

- **URLs:** file-based routes in [`src/routes/`](src/routes/) only—no `src/pages/`.
- **One file per route:** page + `export const Route = createFileRoute(...)` in **`index.tsx`** (layouts use **`route.tsx`**).
- **`_` prefix:** pathless layout routes ([docs](https://tanstack.com/router/v1/docs/framework/react/routing/file-naming-conventions)).
- **`-` prefix:** ignored by the router (`-components/`, `-lib/`, …).
- **Route tree:** autogenerated `src/routeTree.gen.ts`—do not edit or commit.
- **Data:** prefer route `loader` + `pendingComponent` over `useEffect` + imperative `rpc`.

### Route folder layout

```
routes/<segment>/.../
  index.tsx          # Page + createFileRoute (or route.tsx for layouts)
  -components/       # Presentational UI for this route
  -lib/
    hooks/           # controllers (no JSX)
    context/         # route-scoped providers
    utils/           # helpers
    types.ts         # Zod/types for this flow
```

No other top-level siblings under the route directory (`hooks/`, loose `*.ts`, etc.).

### Lift rule (`lib/` vs route-local)

| Used by | Put it in |
|---------|-----------|
| One route tree only | That route's `-components/` or `-lib/` |
| 2+ unrelated route trees | `lib/domains/<context>/` |
| Design system (shadcn) | `lib/components/ui/` |
| Wallet / SDK bootstrap | `lib/web3/`, `lib/filosign/`, `lib/auth/` |
| Pure helpers | `lib/utils/` |
| App chrome / media | `lib/components/app/` |

**`lib/` must not import from `routes/`.** Shared envelope types: `lib/domains/files/envelope-form-types.ts`.

### Layouts

- `dashboard/route.tsx` — [`DashboardProtector`](src/lib/auth/dashboard-protector.tsx) + `Outlet`
- `dashboard/_shell/route.tsx` — sidebar/nav shell + `Outlet`
- Full-bleed flows (envelope create, sign, signature create) are **siblings** of `_shell/`, not children

## TanStack Query

Two key systems—use the right one.

### 1. oRPC API data

Keys come from **`useFilosignContext().rpcQuery`**, prefix `["filosign", <domain>, …]`.

```ts
const { rpcQuery, isAuthed } = useFilosignRpc(); // apps: use domain hooks; SDK internals only

useQuery({
  ...rpcQuery.files.list.received.queryOptions(),
  enabled: isAuthed,
  select: (data) => data.files,
});
```

- **Fetch:** spread `queryOptions()` from the procedure helper.
- **Invalidate one procedure:** `rpcQuery.files.list.received.key()`
- **Invalidate a domain:** `rpcQuery.sharing.key()` (prefix match—all procedures under sharing)
- **Optional `enabled`:** pass `{ enabled: open }` on SDK hooks when data is not needed on mount (e.g. notifications popover).

Multiple observers with the same `queryKey` share one request (React Query dedupes). Documents and notifications both use `useReceivedFiles()` → same key → one network call when both are enabled.

### 2. Non-oRPC and derived client data

Wallet, on-chain reads, session, and UI-only caches use **`filosignKeys`** from [`@filosign/react/query-keys`](../../packages/react-sdk/src/lib/query-keys.ts).

Client import hub: [`src/lib/query/query-keys.ts`](src/lib/query/query-keys.ts) (re-exports SDK keys).

```ts
import { filosignKeys } from "@/src/lib/query/query-keys";

useQuery({
  queryKey: filosignKeys.decryptedFileMetadata(pieceCid, orgDecryptEligible),
  queryFn: /* … */,
});
```

| Key factory | Purpose |
|-------------|---------|
| `filosignKeys.authedApi(address)` | JWT session query |
| `filosignKeys.keyRegistrySnapshot(address)` | On-chain registration + keygen |
| `filosignKeys.isLoggedIn(address)` | Seed matches commitments |
| `filosignKeys.decryptedFileMetadata(…)` | Document card preview cache |

**Static roots** (no `rpcQuery` in scope): `filosignQueryRoots.sharing`, `.files`, `.users`, `.orgs`, …—aligned with oRPC paths.

**Predicates** for `refetchQueries`:

```ts
import {
  filosignNonRpcRoots,
  queryKeyHasNonRpcRoot,
} from "@/src/lib/query/query-keys";

predicate: (q) =>
  queryKeyHasNonRpcRoot(q.queryKey, filosignNonRpcRoots.authedApi),
```

### Invalidation

Prefer grouped helpers from [`@filosign/react/invalidate-queries`](../../packages/react-sdk/src/lib/invalidate-queries.ts). Client re-export for inbox: [`src/lib/query/invalidate-inbox.ts`](src/lib/query/invalidate-inbox.ts).

| Helper | When |
|--------|------|
| `invalidateInboxQueries(qc, rpcQuery)` | Notifications: received files + share requests |
| `invalidateSharingQueries(qc, rpcQuery)` | Connections / sharing domain |
| `invalidateConnectionsContactsTab` / `invalidateConnectionsRequestsTab` | Connections tab switch |
| `invalidateOrgsQueries(qc, rpcQuery)` | Org membership / settings mutations |
| `invalidateAuthQueries(qc, address)` | After login or recovery |
| `invalidateUserProfile(qc, rpcQuery)` | Profile or email changes |

All helpers take `(queryClient, rpcQuery)` when touching oRPC—get `rpcQuery` from `useFilosignContext()` in controllers.

**App-only `useQuery`:** add a named factory on `filosignKeys` in the SDK if the query is reusable; keep one-off keys in the route hook only when truly local.

### Batching

- [`useFileInfosByPieceCids`](src/lib/domains/files/hooks/use-file-infos-by-piece-cids.ts)—piece detail per CID, deduped
- SDK `useProfilesByAddresses`—profile lookup per address (cached; used on add-sign when wallets are set)

Do not mount per-row `useQuery` in lists; batch at the controller.

### Deferred fetch

Gate expensive lists until the UI needs them: `useReceivedFiles({ enabled: open })`, empty `pieceCids` when disabled. Route-level lists (e.g. Documents) stay `enabled: true` by default; cache is shared when the shell loads the same procedure later.
